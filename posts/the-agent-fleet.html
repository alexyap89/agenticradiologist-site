The agent fleet: what I actually run on my own hardware

By Alexander Yap · 8 Jun 2026

People ask what an “agentic radiologist” means in practice, usually with the expectation that the answer will match the Instagram handle. It doesn’t. Right now I run five small agents on one machine. That is the whole fleet. It is less dramatic than the brand, and considerably more useful.

The five

  • Inbox triage. Reads my email, sorts it, drafts replies where a reply is warranted, and produces a short morning digest. The drafts are never sent. I edit or discard. This one saves me the most time and has the fewest failures.
  • Literature reader. Watches a fixed list of arXiv categories and a handful of PubMed queries every night, and produces a two-page summary on Sunday. “Notable because” is the field I care about; abstract concatenation is the failure I’ve had to weed out.
  • Pipeline QA. Watches the logs of the DICOM-to-3D-printing pipeline in the lab and flags anomalies: geometry failures, calibration drift, print-job stalls. It is a monitoring system that happens to be an LLM, which is exactly the kind of boring job models are good at.
  • Report sandbox. Practices drafting report structure on synthetic data only. Deliberately. No real patient, ever, at any stage. Its job is to keep its skills warm and measurable, not to touch clinical care.
  • The digester. Once a week it reads what the other four did and writes a summary of the fleet. Agents reporting on agents sounds like a horror story until you notice it is just monitoring, and monitoring is what we already do to every piece of medical equipment.

The stack is prehistoric on purpose

One Linux box, local models, plain Python, one file per agent, git for state. Memory is a directory of markdown files. There is no framework, no orchestration layer, no dashboard I needed to build because a framework made me. The entire fleet fits in one repository I could read in an afternoon, and I mean that as the primary selling point.

What broke

Three honest failures, and the fixes were all unglamorous. First, a loop: an agent called a tool, got a result, and called the same tool again with slightly different arguments, for an hour. Fix: a per-task budget on tool calls. Second, context rot: long-running summaries quietly drifted from the source material. Fix: shorter windows and re-grounding against the document each pass. Third, tone: models state things with the confidence of people who have never been wrong, and that reads as authority in a medical context. Fix: the output template demands a caveats line, and I review it.

The boundary is the design

The rule that none of this touches patient data is not a compliance afterthought; it is the load-bearing wall. Because it holds, everything else can be loose — loose file formats, loose scripts, my own sloppy naming. In medicine the interesting research question is not “can we build a better agent” but “which problems are safe to hand to software.” The fleet exists to keep my hands on that question.

None of this is special: a few hundred lines each, no launch, no demo video worth making. The fleet is boring on purpose. Boring is what you want at 2 a.m. — in the hospital and in the server rack.
